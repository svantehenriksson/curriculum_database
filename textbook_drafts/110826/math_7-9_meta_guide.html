Why the curriculum uses both tavoitteet and sisältöalueet

In plain language:

  • Tavoitteet answer: what kind of learner capability should be built? (reasoning, communication, problem solving, digital use, responsibility, etc.)
  • Sisältöalueet answer: what mathematical domain/content should be taught? (numbers, algebra, functions, geometry, statistics/probability).

If only objectives existed, teachers could know the skill direction but not the content envelope. If only content areas existed, teachers might "cover chapters" without building mathematical habits and competencies.

So the structure is intentional: competency axis + content axis. Good teaching units should explicitly map both.

National curriculum translated into concrete teaching obligations (Grades 7-9)

This section is intentionally exhaustive for textbook planning. It includes all named national math content areas (S1-S6) and all objectives (T1-T20) for grades 7-9, translated into concrete teachable topic obligations.

Reference view (national grade 7-9 math): ePerusteet national mathematics page.

Important design decision: You can categorize core chapter content under S1-S6, but you must still track T-objectives in parallel. If you classify only by S-areas, you will miss mandatory competency requirements (communication, responsibility, critical evaluation, ICT use, motivation, self-regulation).

B) Full T1-T20 objective-to-content implications (what must be teachable, even if less "chapter-like")

Objective Concrete implementation requirement for textbook + teacher guide
T1 Motivation and positive learner identity Recurring low-stakes entry tasks, growth-feedback prompts, and visible success pathways.
T2 Responsibility for learning (alone + together) Self-goal pages, team problem episodes, and reflection checkpoints in each unit.
T3 Seeing mathematical connections Cross-topic "link boxes" (e.g., percent ↔ linear model ↔ statistics context).
T4 Precise oral/written mathematical expression Explicit language tasks: "write your method", argument sentence stems, notation checks.
T5 Logical and creative problem solving Non-routine tasks with multiple paths, not only one-template exercises.
T6 Evaluate and improve own solutions; reasonableness checks Mandatory verification routines: estimate-check-critique before final answer.
T7 Apply math in other subjects and society Context clusters: science data, finance, civic graphs, practical measurement.
T8 Information handling and critical reading Data-claim critique tasks and source quality questions in statistics/modeling chapters.
T9 Use ICT in study and problem solving Planned tool usage (graphing, spreadsheet, geometry software), not optional side note.
T10 Mental arithmetic and reasoning strength Frequent head-calculation drills + explain-why mini-questions.
T11 Rational-number operation fluency Systematic fluency progression with varied representations and word problems.
T12 Extend number concept to real numbers Explicit treatment of irrational numbers and placement on number line.
T13 Deepen percent understanding Include base value, changed value, comparison and change percentages.
T14 Unknown concept and equation solving From single equations to systems and interpretation of solutions.
T15 Variable + function + graph interpretation/production Coordinate tasks in all three forms: symbolic, tabular, graphical.
T16 Geometry concepts and relationships Concept maps and theorem-relationship tasks, not only formula plugging.
T17 Use right-triangle and circle properties Pythagorean and circle applications in authentic problem contexts.
T18 Area and volume skills 2D-3D progression with unit conversion and mixed-shape decomposition.
T19 Statistical indicators and probability Compute and interpret summary measures + probability in contextual datasets.
T20 Algorithmic thinking + programming in problem solving Structured algorithmic tasks and at least lightweight coding/simulation components.

C) Can we categorize everything under S1-S6 only?

Partly yes for content scope; no for compliance completeness. S1-S6 is excellent for chapter architecture, but it does not fully capture all required performance expectations from T-objectives. The biggest risk areas if you use only S-categories:

  • learner agency and responsibility routines (T1-T2),
  • communication precision (T4),
  • solution critique and reasonableness checks (T6),
  • cross-subject application framing (T7),
  • regular and intentional ICT integration (T9),
  • algorithmic/programming competency as a method, not only a topic mention (T20).
Recommended production model: primary classification by S1-S6 plus a mandatory "T-coverage checklist" per chapter, so nothing explicit or implicit is dropped.

D) Optional-but-pragmatic topics (not always explicit as named items, but standardly needed)

  • Error taxonomies (common mistakes and why they happen).
  • Structured strategy selection ("which method and why").
  • Calculator/spreadsheet hygiene and reproducible workflow habits.
  • Data ethics micro-cases when interpreting charts/claims.
  • Mini capstone cycles each year integrating S2+S3+S4+S6 in one project.

Short summary of irreconcilable differences (with current evidence)

  • Pacing conflict: Some locales are balanced (Helsinki style), others are clearly grade-9-heavy (Kirkkonummi/Kyrkslätt/Vaasa patterns). A single rigid sequencing cannot fully match both.
  • Specificity conflict: Some curricula specify concrete grade-level math actions, while others phrase many targets as broader competencies (communication/responsibility/critical review).
  • Digital/programming intensity conflict: Some local texts foreground digital tools and algorithmic thinking more explicitly than others.
  • Topic granularity conflict: In some places, geometry/algebra are fine-grained; in others, statements remain high-level and require teacher decomposition.
Practical conclusion: design a common core sequence plus municipal pacing adapters, not one immutable chapter order for all.

Suggestions A-E: textbook outline strategies within curriculum guardrails

Suggestion A - Stable Core + Pacing Adapter

Keep one core 7-9 chapter architecture, but provide municipal pacing maps (Balanced vs Back-loaded).

Suggestion B - Dual-Axis Chapter Template

Every chapter explicitly has: (1) content targets (sisältöalueet), (2) capability targets (tavoitteet). This directly mirrors how OPS is structured.

Suggestion C - Core / Flex / Bridge Layers

Mark each topic as Core (must teach), Flex (moveable between grades), or Bridge (supports 2nd stage readiness). This helps reconcile city pacing differences.

Suggestion D - Competency Weaving, Not Add-On Pages

Integrate digital tools, communication, and reasoning into content chapters; do not isolate them as detached appendices.

Suggestion E - Bilingual Semantic Pairing

Build FI/SV term pair tables per chapter so teachers can align intent even when phrasing differs across language versions.
